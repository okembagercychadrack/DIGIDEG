## Getting Started

Use Node.js 22.12 or newer and npm. Create a `.env` file from `.env.example`,
then install the dependencies:

```bash
copy .env.example .env
npm install
```

If npm reports that package install scripts are waiting for approval, approve
the pending scripts and run the install again. This is required for Prisma and
the native SQLite adapter:

```bash
npm approve-scripts --allow-scripts-pending
npm install
```

The `postinstall` script generates Prisma Client automatically. It can also be
run explicitly with `npm run db:generate`.

Start the development server:

```bash
npm run dev
# or
yarn dev
# or
pnpm dev
# or
bun dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `app/page.tsx`. The page auto-updates as you edit the file.

This project uses [`next/font`](https://nextjs.org/docs/app/building-your-application/optimizing/fonts) to automatically optimize and load [Geist](https://vercel.com/font), a new font family for Vercel.

## Vercel Environment Variables

Create a hosted PostgreSQL database (Neon is a simple option), then import the
repository into Vercel. Add these environment variables in the Vercel project
settings for `Production`, `Preview`, and `Development`:

- `DATABASE_URL`: the PostgreSQL connection string, including `sslmode=require`
- `UPLOADTHING_TOKEN`: a token generated by UploadThing
- `NEXT_PUBLIC_APP_URL`: the deployed URL, for example `https://app.example.com`

Set the Vercel build command to `npm run vercel-build`. It applies the Prisma
migrations before building the Next.js application. Run `npm run db:seed` once
against the production database only if the demonstration agents are wanted.

The UploadThing token previously present in local files must be revoked and
regenerated before deployment.
